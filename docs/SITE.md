# Сайт клуба и мини-приложение в Telegram — план (утверждён владельцем 13.11.2026)

Ориентир — приложение игрока в ELO Club (eloclubcrm.store). Правила записи — из обсуждения Этапа 3.

## Решения владельца

- **Сервер — основной.** База одна, на VDS (Timeweb, Россия). Табло и админка клуба открываются через интернет.
  Ноутбук-пакет остаётся запасным вариантом без интернета.
- Сервера и домена пока нет — владелец купит их перед последним шагом по `DEPLOY.md`, пароли в чат не присылает.
- **Сайт для всех (без входа):** расписание и запись, рейтинг, итоги турниров, о клубе.
  Публично — только имена, места, очки. Телефоны, касса, долги — никогда.
- **Вход игрока:** через Telegram (в мини-приложении — сам, на сайте — кнопкой) **и** по логину и паролю.
  Привязка к базе клуба — по подтверждённому в Telegram номеру телефона.
  Логин и пароль (предложение, владелец согласился с планом): игрок задаёт сам в профиле после входа через
  Telegram; тем, у кого Telegram нет, выдаёт админ в карточке игрока. Свободной регистрации по номеру нет.
- **Запись на турнир:** можно «+1…+3» (гости занимают места), лимит мест — по желанию для каждого турнира,
  лист ожидания, отмена до начала.
- **Сообщения:** напоминание записавшимся утром в день турнира; анонсы — всем, с возможностью отписаться.
- Бота создаёт владелец через @BotFather (инструкция — на шаге 5).

## Порядок работ (решение владельца 13.11.2026)

**Сначала всё делаем и проверяем на компьютере, переезд на сервер — в самую последнюю очередь.**
Перед каждым шагом — подробно уточнить у владельца все правила. Токен бота владелец получит в @BotFather.

Что можно проверить на компьютере, а что — только на сервере:
- сайт, расписание, запись, вход по логину и паролю, профиль игрока — полностью на компьютере;
- бот (кнопки, сообщения, напоминания, анонсы) — на компьютере, с **тестовым** ботом (работает, пока запущена программа);
- мини-приложение — страницы те же, что у сайта; на компьютере проверяются в браузере. Внутри самого Telegram
  мини-приложение и кнопка «Войти через Telegram» на сайте требуют адрес с https — их финальная проверка на сервере
  (или через временный https-адрес — спросить владельца).
- Токен бота — секрет: владелец вписывает его сам в файл настроек, в чат не присылает.
  Для разработки — отдельный тестовый бот, боевой — при запуске.

## Расписание турниров (шаг 1, сделано 13.11.2026)

Админка → «Расписание» (`/admin/schedule`).

- **Турнир в расписании:** дата, начало, структура (пресет), название (так увидят игроки; не вписали — название
  структуры), лимит мест (пусто — без лимита), примечание для игроков. Цена входа — из структуры.
- **Постоянные дни** («каждую пятницу в 19:00»): программа сама ставит турниры на **2 недели вперёд** (считая сегодня).
  Поправили постоянный день — меняются его будущие турниры, кроме тех, что правили вручную.
  Сменили день недели — турниры переезжают на новый день. Убрали — будущие турниры пропадают.
- **Отдельный турнир** добавляется вручную («+ Турнир»): финал, праздник.
- **Отменить** — турнир остаётся в списке зачёркнутым и заново не ставится; можно **вернуть**.
- **«Открыть турнир»** (кнопка у сегодняшних): турнир становится текущим — его структура, название, учёт «По игрокам»;
  прошлый уходит в историю. Нельзя, пока текущий турнир идёт или в нём уже отмечены игроки.
  Открыть турнир по-старому («Загрузить пресет» в «Управлении») тоже можно — как раньше.
- **Запись игроков через сайт и Telegram — до старта турнира** по расписанию (решение владельца; шаг 4).
- Дата и время — по часам клуба (московское время), от часового пояса сервера не зависят.

Код: правила — `src/lib/schedule.ts` (чистые функции), база — `src/lib/db/schedule.ts` (миграция 7: `schedule`,
`schedule_templates`), API — `/api/schedule`, страница — `src/app/admin/schedule/page.tsx`.

  Без телефона, денег и долгов.

## Вход игрока и профиль (шаг 3) — ответы владельца 14.11.2026

- **Регистрация:** игрок сам на сайте (`/profile`): имя, телефон, пароль (от 6 символов). Логин — телефон.
  Заявку **подтверждает админ** («Игроки» → «Заявки на вход на сайт»): телефон есть в базе — вход привязывается
  к этому игроку; нет — создаётся новый игрок (новички регистрироваться могут). Админ может привязать и к другому
  игроку вручную. До подтверждения человек видит «Заявка ждёт подтверждения».
- **Пароль:** меняет сам игрок (нужен текущий; другие устройства выходят). Забыл — админ в карточке игрока
  нажимает «Сбросить пароль» и диктует временный (виден один раз). «Отключить вход» — если привязали не к тому.
  8 неверных паролей подряд — пауза 10 минут.
- **Ник:** игрок меняет сам; чужой ник (без учёта регистра) взять нельзя. Правка пишется в журнал.
- **Фото:** ставит игрок в профиле и админ в карточке игрока, **видно сразу**; неподходящее админ убирает.
  Нет фото — первая буква ника. Картинка уменьшается в браузере до квадрата 320 px (JPEG), хранится в базе.
- **Долг** игроку в профиле **не показываем**.
- **Финал в кабинете:** по каждому идущему периоду — «Вы в зоне финала: N место» или «До зоны финала — X оч.».
  Период закрыт, игрок в финалистах, финал ещё не сыгран — плашка «Вы в финале» и **сообщение финалистам**
  (один текст для всех, пишет админ: «Расписание» → «Сообщение финалистам»).
- **Достижения:** видны всем, выдаёт система; список владелец пришлёт позже — пока не сделано.
- **«На какие игры записан»** — появится вместе с записью (шаг 4).
- Как устроено: правила — `src/lib/account.ts`, база — `src/lib/db/accounts.ts` (миграция 8: `accounts`,
  `account_sessions`, `player_photos`), cookie `goto_player` (30 дней; в базе только хэш строки из cookie, пароль —
  соль + scrypt). API: `/api/account` (игрок), `/api/accounts` (админ), `/api/photo?id=&v=`, `/api/site?get=photos`.
  UI: `src/components/site/Account.tsx`, `Avatar.tsx`, `useMe.ts`; админка — `src/components/admin/Accounts.tsx`.

## Запись на турниры (шаг 4) — ответы владельца 14.11.2026

- **Кто записывается:** вошедший игрок — кнопкой «Записаться» на карточке турнира; записаться может и тот, чью
  заявку на вход админ ещё не подтвердил (виден под именем из заявки, в админке — с пометкой). Админ записывает
  любого игрока из базы и снимает любую запись («Расписание» → «Записалось…»).
- **Гости:** +1…+3, ник каждого — по желанию. Всем на сайте видно «Саша +2», ники гостей — только в админке.
  В турнире у записанного пометка «+2 гостя» — видно, что прийти должен не один.
- **Срок:** запись — до времени начала по расписанию (админ — и позже). **Отменить запись можно в любой момент**;
  если турнир уже открыт и игрок ещё не отмечен пришедшим, он пропадает и из записавшихся в турнире.
- **Лимит и лист ожидания:** очередь строгая, по времени записи; запись с гостями занимает 1 + гости мест и проходит
  только целиком. Первая, что не поместилась, и все после неё — ждут. Освободилось место — первый из очереди
  проходит сам. Лист ожидания не хранится, а считается (`splitQueue`).
- **«Открыть турнир»:** записанные (прошедшие по лимиту, с известным игроком) попадают в турнир как «записан».
  Записались или подтвердили заявку после открытия — попадают туда же сразу.
- **Личный кабинет:** блок «Мои записи на турниры» — после «Пути в финал», перед статистикой.
- **Путь в финал** — только по идущему месяцу, полосой прогресса: сколько очков есть и сколько нужно для зоны финала.
- **Бонус «приведи друга»:** привёл **новичка** (раньше в клубе не играл) — на эту и только эту игру бесплатный ребай
  или аддон; какой бонус и сколько (один на турнир или за каждого) — задаётся в структуре (`Prices.friendBonus`,
  `friendBonusEach`). В турнире («Управление» → «Игроки») блок «Новички»: у вошедшего новичка админ выбирает, кто его
  привёл (`setBroughtBy`). Следующий ребай (или аддон) приведшего сам становится бесплатным (`events.free = 1`,
  `events.bonus = 'friend'`, миграция 10), пока бонусы не кончились; не пригодился — сгорает. Бонус «аддон» действует
  только на обычный аддон, не на двойной. Считаются только новички, которые вошли в турнир.
- **«Вы придёте?»:** после первого перерыва записанному, который не отмечен пришедшим, уходит вопрос; не ответил —
  запись снимается, когда закроется ребай. Сообщение отправляет бот — делается вместе с ботом (шаг 5).
- Как устроено: правила — `src/lib/signup.ts`, база — `src/lib/db/signups.ts` (миграция 9: `signups`,
  `participants.brought_by`), API `/api/signup` (игрок), действия `signupAdd` / `signupRemove` в `/api/schedule`.
  UI: `src/components/site/Signup.tsx`, админка — `src/components/admin/Signups.tsx`.
