# ГОТО ПОКЕР — система управления клубом

Клуб спортивного покера «ГОТО ПОКЕР» (Воронеж). Владелец — Николай: не профессиональный
программист, общаемся **по-русски**, объясняем просто, без жаргона. Интерфейс приложения — на русском.

Цель: своя система управления клубом (ориентир по функциям — ELO Club, eloclubcrm.store).
**Сейчас** всё работает на ноутбуке в баре (Windows, офлайн) — это **временно**.
**Целевая схема** — VDS-сервер (Timeweb, Ubuntu; скрипты `deploy/`, `DEPLOY.md`) + Telegram-бот /
Telegram Mini App для игроков. Архитектуру делать так, чтобы переезд на VDS был простым
(та же сборка, данные в одной базе, никакой привязки к Windows в логике). План — `docs/ROADMAP.md`.

## Документы

- `docs/ROADMAP.md` — план работ по этапам.
- `docs/RATING.md` — **утверждённые владельцем** правила рейтинга, финалов, ведения турнира
  и рейтинга на табло. Делать строго по ним; всё, чего там нет, — спросить.
- `docs/CASH.md` — утверждённые правила кассы (цены, оплаты, бесплатно, долги).
- `docs/STATS.md` — правила подсчёта статистики клуба.
- `docs/SEATING.md` — правила рассадки за столами (автопосадка, стек, подсказки).
- `docs/SITE.md` — утверждённый план сайта клуба и мини-приложения в Telegram (Этап 3).

## Стек и важные особенности

- **Next.js 16.4 (App Router) + React 19.3 + Tailwind 4 + TypeScript.** Это НЕ та Next.js,
  что в обучающих данных: перед кодом читай `node_modules/next/dist/docs/` (см. `AGENTS.md`).
- `next.config.ts`: `cacheComponents: true` → **в клиентских компонентах нельзя вызывать
  `Date.now()`, `Math.random()`, `new Date()` во время рендера** (страница зависает при пререндере).
  Время — только в `useEffect`/колбэках (см. `useTournament.ts`). В route handlers, читающих
  данные, вызывай `await connection()`.
- Страницы — клиентские компоненты, данные через route handlers `src/app/api/**`.
  Синхронизация: клиенты опрашивают `/api/state` (~1–1.5 с), часы тикают локально с поправкой
  на время сервера. Табло и админка открыты на разных устройствах одновременно.
- Хранилище — SQLite `DATA_DIR/goto-poker.db` через **встроенный `node:sqlite`** (Node 22),
  **без нативных модулей** (better-sqlite3, sharp и т.п.), пока используется Windows-пакет:
  он собирается на Mac, нативные бинарники его сломают. На VDS ограничение снимается,
  но SQLite остаётся подходящей.
  - `src/lib/store.ts` — `readDb()` / `updateDb()` (очередь записи, кэш в памяти) отдают объект `Db`
    (пресеты + текущий турнир) — тот же формат, что был с JSON; табло и админка его и используют.
  - `src/lib/db/schema.ts` — миграции по `PRAGMA user_version`. **Выпущенные миграции не менять**,
    изменения схемы — только новой миграцией в конец списка. База от более новой версии не открывается.
  - `src/lib/db/sqlite.ts` — открытие базы (WAL, `synchronous=FULL`), `transaction()`,
    `loadState` / `writeState` (Db ↔ таблицы `presets`, `tournaments` с `is_current = 1`, `board`),
    первый запуск: перенос `goto-poker.json` → копия в `backups/`, исходник → `goto-poker.json.migrated`.
    Если SQLite не открылась, а JSON ещё на месте, `store.ts` работает по-старому на JSON.
  - `src/lib/db/backup.ts` — копии `backups/goto-poker-ДАТА_ВРЕМЯ-start|finish.db` (`VACUUM INTO`)
    при запуске сервера и при завершении турнира, по 30 каждого вида.
  - `node:sqlite` и `node:fs` в `src/lib/db/` берутся через `process.getBuiltinModule(...)`, а пути
    в `store.ts` — строкой-литералом: иначе Turbopack пишет «Dynamic filesystem access» и тянет
    в standalone-пакет весь проект (`data/`, `dist/`). После правок хранилища проверять, что
    `npm run build` идёт без этого предупреждения.
  - Схема заранее содержит таблицы под Этапы 1–2: `players`, `participants`, `events`
    (журнал входов/re-entry/аддонов/вылетов — источник правды для мест и KO), `knockouts`
    (доли 1 / 0,5), `periods`, `tournament_periods`, `period_standings`, `finalist_changes`,
    `rating_rules` (версии правил), `settings`, `audit_log`.
  - Любое изменение данных турнира должно обновлять `tournament.updatedAt`: клиент
    (`useTournament.ts`) отбрасывает ответы, у которых оно не новее.
- Логика часов — чистые функции в `src/lib/clock.ts` (`resolveClock`, `applyAction`, `boardView`),
  общие для сервера и клиента. Новую бизнес-логику (рейтинг, итоги) тоже делать чистыми функциями
  отдельно от UI и покрывать тестами.
- Авторизация: `src/lib/auth.ts` — пароль админки из env, cookie `goto_admin` (HMAC).
  **Пароль владельца** (`src/lib/db/owner.ts`, `src/lib/owner.ts`, `/api/owner`, UI `src/components/admin/Owner.tsx`):
  открывает «Статистику» и изменение правил рейтинга (PUT rules/settings, POST rescore — `isOwner` + `ownerRequired`).
  Хранится в `settings` (ключ `owner`, соль + scrypt), задаётся в админке при первом входе, cookie `goto_owner` (12 ч).
  Сброс: файл `DATA_DIR/reset-owner-password.txt` (на ноутбуке — `RESET-OWNER-PASSWORD.bat`).
- Дизайн: тёмный фон `#080e15`, панели `#101923` с рамкой `white/[0.09]`, акцент `amber-300`,
  крупные цифры `tabular-nums`. Компоненты админки — `src/components/admin/ui.tsx`.
  Логотип — `src/assets/logo.png`.

## Запуск и сборка

- Разработка: `npm run dev` → табло `http://localhost:3000`, админка `/admin` (пароль по умолчанию `goto`).
  С телефона в dev: `http://IP-мака:3000` (разрешено через `allowedDevOrigins`).
- Проверки перед сдачей работы: `npx tsc --noEmit`, `npm run lint` и `npm test` (vitest,
  тесты рядом с кодом: `src/**/*.test.ts`) — без ошибок. Тесты должны проходить и на Node 22,
  как в пакете: `npx -y node@22 node_modules/vitest/vitest.mjs run`.
- Терминал должен быть открыт в папке проекта (`cd ~/Projects/goto-poker`), иначе npm не найдёт `package.json`.
- **Основной вариант работы в клубе — ноутбук на Windows** + HDMI к ТВ:
  `./deploy/build-windows.sh` (на Mac) → `dist/GOTO-Poker-Windows.zip`
  (standalone-сборка `BUILD_STANDALONE=1`, `node.exe` внутри, скрипты `deploy/windows/`).
  Персонал не технический: всё должно запускаться ярлыком, без консоли и настроек.
  `.ps1` при сборке конвертируются в UTF-8 с BOM + CRLF. Данные на ноутбуке: `GOTO-Poker\data`.
  `build-windows.sh` удаляет всю папку `dist/` — если там лежит нужный старый архив, сохранить его заранее.
  Сервер запускается с `--disable-warning=ExperimentalWarning` (`start.ps1`), чтобы предупреждение
  о SQLite в Node 22 не шло в `server-errors.log`.
  Телефоны подключаются по Wi-Fi клуба (`LAN_MODE=1`, адрес админки показывается внизу табло).
  Известная проблема: роутер бара изолирует клиентов Wi-Fi → телефоны не видят ноутбук
  (решается роутером/кабелем/Tailscale, не кодом).
- Запасной вариант — VDS: `deploy/setup.sh`, `deploy/push.sh`, `DEPLOY.md`.
- После изменений, влияющих на пакет, напомнить владельцу пересобрать `build-windows.sh`.

## Термины предметной области

- **Спортивный покер**: призы — не деньги, а очки/рейтинг. **CP** — клубные очки за места
  (призовой фонд CP турнира зависит от входов/аддонов), **ELO** — рейтинг силы игрока,
  **KO** — выбивания (нокауты).
- **Вход / re-entry / ребай** — повторный вход после вылета; **аддон** и **двойной аддон** —
  докупка фишек (обычно на перерыве, когда закрываются ребаи).
- **Серия / лига** — зачёт из нескольких турниров со своими правилами начисления; один турнир
  может входить в несколько серий.
- **Check-in** — игрок пришёл и подтверждён; **рассадка** — стол и место; **ITM** — призовые места.

## Как работать

- Делать маленькими шагами, каждый шаг — рабочее состояние; перед большими изменениями
  кратко описать план владельцу и дождаться «ок».
- Не ломать табло и админку турнира: это используется на живых турнирах.
- Неясные правила (формулы рейтинга, начисление CP) — **не выдумывать**, спросить владельца,
  предложить 2–3 варианта с примером расчёта.
- Коммитить в git после каждого завершённого шага с понятным сообщением на русском.
